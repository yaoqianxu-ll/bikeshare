# VIP 支付宝生产防错设计

**日期：** 2026-05-31
**范围：** `bickdemo-backend` VIP 支付链路与 `sshserver2` 支付宝生产配置

---

## 背景

`sshserver2` 当前生产容器实际配置为 `ALIPAY_SANDBOX=true`。这会导致生产环境：

- 下单使用沙箱网关
- 前端打开沙箱兜底分支
- 后端允许前端手动确认支付
- 主动查单出现“验签失败，请检查支付宝公钥设置是否正确”

根据支付宝官方沙箱说明，沙箱与生产环境完全隔离，沙箱调试完成后仍必须切换到生产环境配置并完成线上验收。

## 目标

- 明确阻止生产环境误用沙箱链路。
- 保留非生产沙箱联调能力，不影响本地调试。
- 让生产环境在支付配置错误时快速暴露，而不是偷偷退回沙箱链接。

## 方案

### 1. 支付宝运行环境策略

新增一个小型运行环境策略对象，统一判断：

- 当前是否激活 `prod`
- 当前是否启用支付宝沙箱
- 是否允许沙箱兜底链接
- 是否允许前端手动确认支付

规则：

- 只有“非 `prod` + `sandbox=true`”时允许沙箱联调兜底。
- 其他场景全部视为正式支付链路。

### 2. 下单与兜底行为收敛

`VipOrderServiceImpl#generatePayUrl` 调整为：

- 非生产沙箱且未完整配置支付宝时，仍可返回模拟支付链接。
- 正式链路若缺少关键配置，直接抛出明确异常。
- 正式链路若 SDK 调用失败，直接抛出明确异常，不再回退到沙箱 URL。

### 3. 前端确认支付入口收敛

`VipController#confirmPayment` 调整为基于统一策略判断，而不是仅看 `alipaySandbox`。

- 非生产沙箱允许手动确认，用于联调。
- `prod` 环境一律拒绝前端手动确认支付。

### 4. 启动期提示

`AlipayConfig` 在初始化日志中增加明显提示：

- 标明当前连接的是沙箱还是正式网关
- 当 `prod` 环境仍启用沙箱时输出高风险告警日志

### 5. 生产配置修复

修复 `sshserver2:/opt/bickdemo/.env`：

- `ALIPAY_SANDBOX=true` -> `false`

并重启应用容器验证。

## 测试策略

- 单元测试覆盖运行环境策略。
- 单元测试覆盖 `generatePayUrl` 在不同环境下的行为。
- 单元测试覆盖 `confirmPayment` 对生产环境手动确认的拒绝行为。
- 生产验证查看容器环境、启动日志与新订单日志，不出现沙箱模式与验签失败。
