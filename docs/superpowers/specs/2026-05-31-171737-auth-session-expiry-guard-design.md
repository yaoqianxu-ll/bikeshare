# 会话过期单次提示修复 - 设计规范

## 1. 背景

用户端 `bickdemo-frontend` 和管理端 `bickdemo-admin` 都存在同类问题：当本地保存了已过期的 JWT token 时，前端仍会把用户视为“已登录”，允许进入受保护页面。页面挂载后会并发触发多个受保护请求，后端连续返回 401，最终在页面上堆出多条“未登录或 Token 已过期”提示。

本次任务目标不是单纯压制 toast，而是修正过期会话链路，让两个前端都满足：

1. 过期 token 不再被当成有效登录态。
2. 同一轮过期事件只提示一次，并只跳转一次登录页。
3. 用户端兼容 HTTP 401 与 `body.code = 401` 两种过期信号。

## 2. 现状分析

### 2.1 用户端

- `src/stores/user.js` 仅用 `!!token` 判断 `isLoggedIn`。
- `src/router/index.js` 的受保护路由守卫只判断 `isLoggedIn`，不会检查 token 的 `exp`。
- `src/api/request.js` 已有 401 处理和 sessionStorage 去重逻辑，但它发生在请求已经发出并收到响应之后。
- `src/views/Layout.vue` 在登录态下会首屏并发拉取 `getCurrentUser`、联系人、通知、活动、租赁、VIP 状态等接口。
- 用户端部分后端接口还会返回 `HTTP 200 + code = 401`，当前 fulfilled 分支只把它当普通失败提示。

### 2.2 管理端

- `src/stores/auth.js` 同样只以 `!!token` 判断 `isLoggedIn`。
- `src/router/index.js` 的后台守卫只判断“有无 token”和角色。
- `src/api/request.js` 用模块级 `authExpiredHandling` 避免重复跳转，但仍然是在请求返回 401 之后处理。
- `src/views/Dashboard.vue` 等后台页面会在 `onMounted` 中并发请求多个后台接口。

## 3. 根因

问题由两个条件叠加触发：

1. **前置判断缺失**：两个前端都没有在进入受保护路由或发起受保护请求前解析 JWT `exp`，导致过期 token 仍被视为有效。
2. **并发请求放大**：进入页面后，大量 `onMounted` 请求同时命中过期会话，toast 去重只能减少一部分重复反馈，却无法阻止无效请求洪峰。

因此，这不是单一 toast 组件的问题，而是“本地登录态判断 + 路由守卫 + 请求拦截器”三段链路没有统一收口。

## 4. 解决方案

### 4.1 引入可复用的 JWT 会话工具

在两个前端分别新增轻量工具模块，负责：

- 解析 JWT payload（兼容 Base64URL）。
- 提取 `exp` 并转换为毫秒时间戳。
- 判断 token 是否已过期。
- 提供一个带冷却窗口的“过期事件标记”能力，保证同一轮过期只执行一次提示/跳转。

之所以独立成工具，是为了让路由守卫、store、请求拦截器共用同一判断逻辑，也便于用纯逻辑测试覆盖。

### 4.2 路由守卫前置拦截

用户端和管理端的受保护路由守卫都要在“进入页面之前”检查：

- 若本地没有 token：按现有逻辑跳登录页。
- 若本地有 token 但 JWT 已过期：立刻清理本地登录态，带上当前地址作为重定向参数（用户端）或直接回到后台登录页（管理端），并阻止页面挂载。

这样可以阻止绝大多数“页面刚打开就连发一串 401”的情况。

### 4.3 请求拦截器发出前兜底

在 axios request interceptor 中，对所有会附带 token 的受保护请求追加过期检查：

- 如果 token 未过期，正常注入 `Authorization`。
- 如果 token 已过期，直接触发统一的会话过期处理，拒绝该请求，不再真正发给后端。

这一步是路由守卫之外的保险丝，用来覆盖：

- 当前页面停留过久，token 在页面停留期间失效。
- 非路由触发的异步请求。
- 首屏并发请求中少数绕过路由守卫时间窗的情况。

### 4.4 响应拦截器统一收口

两个前端都把“会话过期”收口到统一函数处理：

- 登录页上的登录请求 401：只显示登录失败类提示，不做过期跳转。
- 非登录页上的 HTTP 401：执行统一的清理、单次提示、单次跳转。
- 用户端额外处理 `response.data.code === 401`：按会话过期等价处理，而不是当成普通业务错误反复 toast。

统一函数需要保证：

- 同一轮过期事件里只弹一次消息。
- 同一轮里只做一次 `logout` 和一次跳转。
- 成功登录后，过期冷却状态可恢复，保证下一次真实过期仍能提示。

## 6. 测试策略

本次修复按 TDD 进行，先补失败测试，再改实现。

测试分两层：

1. **逻辑测试**
   - JWT `exp` 解析正确。
   - 过期判断正确。
   - 冷却标记在首次触发时生效，冷却期内不会重复触发。
2. **集成行为测试（轻量）**
   - 路由守卫遇到过期 token 时返回登录跳转。
   - 请求拦截器遇到过期 token 时直接拒绝请求，不再注入鉴权头。
   - 用户端对 `body.code = 401` 走统一过期处理路径。

## 7. 非目标

- 不统一改造后端所有 401 返回格式。
- 不重写 toast 组件样式或动画。
- 不修改业务页面的并发加载策略，只修正会话鉴权的入口和兜底链路。
